# Pre-Resolution Context Research Guide

## The Problem

The URLs in `manual_seeds.json` may be:
1. ❌ Fake or auto-generated by LLMs
2. ❌ Articles AFTER the event (about outcomes, not predictions)
3. ❌ Not accessible or behind paywalls

## The Solution

Manually research and document **pre-resolution context** for each event.

## Key Principle: Temporal Validity

```
Event Timeline:
├─ Market Opens: 2024-10-01
├─ [VALID CONTEXT PERIOD] ← Only articles from here
├─ Resolution Date: 2024-11-06
└─ [POST-RESOLUTION] ← NO articles from here
```

## What MiroFish Needs

### ✅ GOOD - Pre-Resolution Context
- "Senate Races 2024: Polls Show Tight Races" (Oct 2024)
- "Election Forecasts: What the Models Say" (Oct 2024)
- "Polymarket Odds: Republicans Favored in Senate" (Nov 5, 2024)
- "538 Forecast: GOP Likely to Win Senate Control" (Nov 4, 2024)

### ❌ BAD - Post-Resolution Results
- "Republicans Win Control of Senate" (Nov 6, 2024)
- "Election Results: GOP Takes Senate Majority" (Nov 7, 2024)
- "How Republicans Won the Senate" (Nov 10, 2024)

## Research Workflow

### Step 1: Understand the Event
- Read the question carefully
- Note the resolution date
- Identify what type of event it is

### Step 2: Define the Context Window
```python
# Example for Senate election (S2)
opened = "2024-10"  # Market opened
resolved = "2024-11-06"  # Resolved

# Valid context window:
# From: opened (2024-10-01)
# To: resolved - 1 day (2024-11-05)
```

### Step 3: Search for Pre-Resolution Content

#### For Political Events:
1. **Polling Aggregators**
   - FiveThirtyEight.com
   - RealClearPolitics.com
   - Look for: "Senate polls 2024" with date filter

2. **Prediction Markets**
   - Polymarket historical data
   - PredictIt historical odds
   - Archive.org for snapshots

3. **Analysis/Forecasts**
   - The Economist forecasts
   - Nate Silver's substack
   - Political analysts' predictions

#### For Economic Events:
1. **Fed/Economic Forecasts**
   - Federal Reserve statements
   - Bloomberg economist surveys
   - CME FedWatch tool

2. **Market Expectations**
   - Futures markets
   - Bond market signals
   - Analyst consensus

3. **Expert Commentary**
   - Bloomberg articles
   - WSJ economic analysis
   - Reuters pre-meeting coverage

#### For Tech Events:
1. **Industry Rumors**
   - TechCrunch speculation
   - The Verge reporting
   - Industry insider leaks

2. **Company Announcements**
   - Official roadmaps
   - Conference presentations
   - Developer comments

3. **Expert Predictions**
   - Analyst reports
   - Tech blogger predictions
   - Industry observer commentary

### Step 4: Archive Research

Use these tools to find historical content:

1. **Wayback Machine (Archive.org)**
   ```
   https://web.archive.org/web/[DATE]/[URL]
   ```
   Example: Find FiveThirtyEight's forecast from Nov 5, 2024

2. **Google Advanced Search**
   - Use "Tools" → "Custom range"
   - Set end date = resolution date - 1 day

3. **NewsAPI / News Archives**
   - Search with date filters
   - Look for "published before [date]"

### Step 5: Document the Context

For each article:
```markdown
### Article 1: 538 Senate Forecast

**Source:** FiveThirtyEight
**URL:** https://projects.fivethirtyeight.com/2024-election-forecast/senate/
**Published:** 2024-11-05 (archived via Wayback Machine)
**Type:** Statistical Forecast

**Key Points:**
- Republicans had 85% chance of winning Senate
- Expected to gain 2-4 seats
- Montana, Ohio, West Virginia most likely flips
- Polls showing GOP leads in key races

**Forecast Data:**
- GOP: 52.3 projected seats (85% confidence)
- DEM: 47.7 projected seats (15% confidence)
- Margin of error: ±1.5 seats

**Relevant Context:**
The model incorporated polling data through Nov 4, showing
Republican leads in Montana (+8), Ohio (+4), and West Virginia (+15).
Model gave Republicans strong odds but noted polling uncertainty
could still allow Democratic holds.
```

### Step 6: Create Comprehensive Context Document

Save as: `ECNBench/data/seeds/[EVENT_ID]/context.md`

```markdown
# Pre-Resolution Context: [Event Question]

**Resolution Date:** [Date]
**Context Cutoff:** [Resolution Date - 1 day]

## Summary
[2-3 paragraph overview of the situation before resolution]

## Baseline Information
[Background: what is this event about?]

## Forecasts & Predictions
[What were experts predicting?]

## Key Uncertainties
[What was uncertain/debated?]

## Articles

[Detailed article summaries]

## Quantitative Signals
- Polymarket: [probability before resolution]
- Polls: [polling data]
- Expert forecasts: [prediction summaries]

## For MiroFish Simulation
This context represents what an informed forecaster would have known
on [date before resolution]. Personas should debate based on this
information without knowledge of the actual outcome.
```

## Quality Checklist

Before submitting context for an event:

- [ ] All articles published BEFORE resolution date
- [ ] At least 3-5 different sources
- [ ] Includes quantitative forecasts (polls, odds, predictions)
- [ ] Includes qualitative analysis (expert commentary)
- [ ] Covers multiple perspectives/arguments
- [ ] NO mention of actual outcome
- [ ] NO post-resolution analysis
- [ ] Sufficient detail for simulation (3,000+ words total)

## Example: Good vs Bad

### Event: "Will OpenAI release GPT-5 in 2024?"
**Resolution:** 2024-12-31, Outcome: NO

#### ❌ BAD Context (Post-Resolution)
```
Article: "Why OpenAI Didn't Release GPT-5 in 2024"
Published: 2025-01-05
Content: "OpenAI failed to release GPT-5 in 2024 because..."
```
**Problem:** This is AFTER the outcome was known!

#### ✅ GOOD Context (Pre-Resolution)
```
Article: "Will GPT-5 Arrive Before 2025?"
Published: 2024-12-15
Content: "Industry experts are divided on whether OpenAI
will release GPT-5 before year-end. Sources close to the
company suggest December is possible but tight. Prediction
markets give it 35% odds..."
```
**Good:** This is what someone would have known before resolution!

## Tips for Efficient Research

1. **Start with prediction markets**
   - They aggregate information efficiently
   - Often have timestamps

2. **Use archive snapshots**
   - Find the page as it existed before resolution
   - Wayback Machine is your friend

3. **Focus on quantitative forecasts**
   - Numbers are more useful than opinions
   - Polls, odds, probabilities, model outputs

4. **Get multiple perspectives**
   - Don't rely on single source
   - Include contrarian views

5. **Document your sources**
   - URLs (including archived versions)
   - Publication dates (verify!)
   - Key quotes and data

## Common Mistakes to Avoid

1. ❌ Using articles published after resolution
2. ❌ Using articles that discuss the outcome
3. ❌ Relying solely on background info (need forecasts)
4. ❌ Ignoring quantitative data
5. ❌ Not verifying publication dates
6. ❌ Using fake or AI-generated content

## Need Help?

If you're unsure whether content is appropriate:
- Check: Is it published before resolution date?
- Check: Does it predict/forecast rather than report outcomes?
- Check: Would this have been available to forecasters?

When in doubt, err on the side of temporal validity!
